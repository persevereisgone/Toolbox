# Toolbox Test Debug

## 目标
为 Toolbox 项目提供稳定、可复现、可定位问题的测试流程，优先发现“用户看不见/看不清/点不到”的 UI 问题，再验证业务流程完整性。

## 别名与触发短语
- 别名：`专用测试技能`
- 典型触发句：
  - “用专用测试技能进行统计模块测试”
  - “用专用测试技能复测并修复问题”
  - “用专用测试技能做 UI 可见性测试”

## 默认执行模式
1. 先输出测试计划（范围、用例、命令、预期结果）。
2. 待用户确认后执行测试。
3. 发现失败时先定位根因，再修复并复测。
4. 输出“问题 -> 修复 -> 验证结果”三段式结论。

## 测试优先级
1. **UI 可见性与可读性**：标题、按钮、提示文案、对话框按钮是否可见，特别关注深色模式下的颜色对比度。
2. **核心流程**：新增/编辑/删除/切换/导入导出等主路径。
3. **回归保护**：修复后补测试，避免同类问题再次出现。
4. **深色模式专项**：检查所有自定义颜色在深色模式下的可读性和对比度。

## 强制必检项（对话框）
每次涉及对话框（创建、删除、批量操作、确认框）时，必须补充并执行以下检测：
1. 按钮存在：`BUTTON_POSITIVE` 与 `BUTTON_NEGATIVE` 非空。
2. 按钮可见：`visibility == View.VISIBLE`。
3. 按钮文字可读：文字长度 > 0，且颜色与背景有对比（优先显式色值校验）。
4. 交互可用：点击确认/取消后，状态变化符合预期。
5. 主题回归：至少在当前主题下跑通过；若改过主题样式，补夜间模式验证。

## 对话框问题兜底规则
- 若发现按钮“存在但看不见”，优先在显示后显式设置按钮文本颜色。
- 不能只靠手测结论，必须补自动化断言再结束任务。

## 推荐命令
```bash
# 统计模块专项（Robolectric/JVM）
./gradlew :app:testDebugUnitTest --tests "*StatisticsManagerRobolectricTest*"

# 全量 Debug 单元测试回归
./gradlew :app:testDebugUnitTest
```

## 调试工作流
1. **复现失败**
   - 先跑模块级测试定位失败用例。
   - 必要时加 `--stacktrace` 或 `--info` 查看上下文。
2. **判定类型**
   - UI 可见性问题：按钮/文本存在但不可见（颜色、主题、背景对比）。
   - 交互问题：点击后状态未变化、对话框未关闭、列表未刷新。
   - 持久化问题：重启或重建后数据丢失/显示错误。
3. **最小修复**
   - 只改与失败直接相关的实现，避免过度改动。
4. **复测闭环**
   - 先跑失败用例，再跑模块回归，最后跑全量单测。

## 测试用例模板
```markdown
### 用例: [名称]
- 场景: [用户操作]
- 前置: [数据/状态]
- 步骤:
  1) ...
  2) ...
- 预期:
  - [可见性]
  - [状态变化]
  - [提示文案]
```

### 对话框用例补充模板（必须）
```markdown
### 用例: [某某对话框按钮可见性]
- 场景: 打开对话框
- 预期:
  - 正向/负向按钮都存在且可见
  - 按钮文字非空
  - 按钮文本颜色符合可读性要求
```

### 深色模式测试用例模板（必须）
```markdown
### 用例: [页面/组件]深色模式显示
- 场景: 系统切换到深色模式后打开页面
- 前置: 应用已启动，系统主题为深色模式
- 步骤:
  1) 切换系统主题为深色模式
  2) 打开目标页面/组件
- 预期:
  - 背景颜色正确切换为深色模式配色
  - 所有文本颜色与背景对比度 ≥ 4.5:1
  - 图标颜色可见且对比度 ≥ 3:1
  - 按钮文字可读，对比度 ≥ 4.5:1
  - 无硬编码颜色导致的显示异常
```

```markdown
## 测试计划

- 用例:
- 命令:

## 执行结果

- 失败:

   修复:
   验证:
```
